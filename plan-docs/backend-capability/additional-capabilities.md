# 최소 목록 밖에서 유지할 기능 경계

2026-10-09 분석·제안. [105개 최소 기능표](capability-matrix.md)의 인증·민감 정보 항목만으로는 아래 업무 수명 계약을 드러내기 어렵다. 원문의 최소 항목 수와 별도로 추적한다. 제품 지원으로 합산하지 않는다.

## K01 — 본인 확인과 계정 수명

- **전통 구현:** 인증 제공자 연동 외에 이메일·전화 확인, 재전송 제한, 일회용 코드 발급·검사·소진, 계정 연결·탈퇴를 Service/Worker에 구현한다.
- **현재 제품:** JWT·principal 연결과 폐기 검사가 있다[P07]. 본인 확인 코드의 공통 제품 계약은 확인되지 않았다. IdP 토큰 검증과 이메일 확인·계정 연결은 별개다.
- **별도 PoC 근거:** `crates/aip-cli/tests/ariari_e2e.rs:312`부터 대상 도메인 거부, 재전송 제한, 코드 해시 저장, 실패 시 남은 시도 횟수 감소, 신청자 바인딩을 검사한다. 이번 ariari 재실행에 포함됐다. 실제 이메일 provider 발송, 비밀번호 재설정·여러 IdP 계정 연결은 이 테스트로 검증하지 않았다.
- **목표 Level:** L1은 코드 생성·검증·재전송/시도 제한, L3는 확인 목적·대상·수명·이후 허용 동작, L4는 특수 신원 검증 provider다. IdP를 다시 구현하는 범용 인증 DSL은 제안하지 않는다.
- **프론트/서버/확장 역할:** 프론트는 허용된 확인 요청·제출을 호출한다. 서버 Specification은 코드의 목적·주체·정책을 고정한다. 표준 전달 adapter 외 특수 provider만 확장한다.
- **안전·실행 제약:** 비밀 코드 반환·로그 노출 금지, 목적/주체/대상 바인딩, 만료·단일 소진, 계정 열거 방지, 실패에도 시도 횟수 보존, 발송과 DB commit 경계를 검사해야 한다. 일반 rollback 규칙을 실패 횟수 기록에 그대로 적용할 수 없다.
- **제거할 반복 구현 가설:** 코드 수명·시도 제한·전달 예약·중복 소진 방어. 서비스별 계정 연결 정책과 복잡한 신원 판정은 남는다.
- **OSS·우선순위:** [Frappe 초대 소스](sources.md)의 대상·역할·만료·중복 수락 검사는 비교 재료다. 초대와 본인 확인을 같은 계약으로 취급하지 않는다. 기반 효과/권한 계약 뒤 P1 후보다.

## K02 — 동의·개인 데이터 수명

- **전통 구현:** 약관 버전·철회 기록, 민감 동작의 동의 검사, 본인 데이터 export/erase, 삭제 시 참조 처리, 보관·정리 Job을 Middleware/Service/Worker에서 조합한다.
- **현재 제품:** 행/필드 가시성은 있으나 동의·개인 데이터 export/erase의 전용 공통 계약은 확인되지 않았다[P01,P06]. 현재 행·필드 가시성만으로는 데이터 수명 정책 전체를 보장하지 않는다.
- **별도 PoC 근거:** `crates/aip-cli/tests/cms_e2e.rs:279`의 동의 버전 변경·철회·이력 보존, `:452` 이후 대리 세션의 export/erase/동의 금지와 본인 export를 검사한다. `ariari_e2e.rs:176` 이후 erase 참조 정리도 검사한다. 이번 25개 PoC 재실행에 포함됐다. IR의 retention/on_erase 선언 존재를 실제 보관 기한 경과·모든 저장소 삭제 검증으로 확대하지 않는다.
- **목표 Level:** L1은 동의/데이터 수명의 공통 기계적 처리, L3는 목적·버전·범위·보관/삭제·대리 금지 정책, L4는 외부 시스템별 export/erase adapter다. 법률 적합성을 자동 보장한다는 주장은 하지 않는다.
- **프론트/서버/확장 역할:** 본인은 허용된 조회·동의·철회·export 요청을 호출한다. 서버 Specification이 필요한 범위와 제한을 정의한다. 외부 저장소의 정리 동작은 capability 계약을 지키는 adapter로 연결한다.
- **안전·실행 제약:** 실행 시점의 본인/대리·tenant 권한 재검사, export 파일 권한·만료, erase와 감사/업무 불변조건의 충돌, DB·파일·외부 provider 부분 실패·재시도·진행 상태를 정의해야 한다. 삭제 결과를 일반 성공 응답 하나로 숨기지 않는다.
- **제거할 반복 구현 가설:** 버전별 동의 검사·철회 기록, 본인 요청 공통 권한, export 작업·결과 수명, 삭제 상태 추적. 프로젝트별 삭제 범위·예외 정책은 L3에 남는다.
- **OSS·우선순위:** 이번에 대조한 외부 앱에서 이 전체 수명 계약까지 검증하지 않았다. 현재 근거는 AIP PoC이며 외부 구현 비교는 확인 필요다. 파일/Job/외부 효과 기반 계약 뒤 P1 후보다.

두 후보 모두 이번 단계에서는 제품에 이식하지 않았다. PoC의 actor/session·IR·DB 결합을 먼저 분석하고 기존 제품의 정책·멱등·배포 계약과 함께 반례를 검증해야 한다. [로드맵](roadmap-and-risks.md)의 수직 검증 관문을 적용한다.
