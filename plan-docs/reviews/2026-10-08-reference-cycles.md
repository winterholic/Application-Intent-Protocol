# 실제 `Ref<T>` 순환의 DDL 실행

> 상태: V1이 이미 허용하는 참조 그래프의 V2 생성·제품 마이그레이션 누락 보완. 공개 소스의 특정 모델과 동등하다는 주장은 하지 않는다.

`Member.dept: Dept?`와 `Dept.lead: Member?`는 V1에서 성공 facts를 만든다. V2는 각 테이블의 상대 테이블 선행 생성을 요구하다가 순환 오류를 낸다. 비순환 정의는 기존 위상정렬 결과를 그대로 쓴다. 위상정렬이 멈추면 미완료 참조를 반복 추적해 실제 순환에 속한 테이블을 고르고, 그 테이블에서 아직 생성되지 않은 대상 FK만 열 생성에서 분리한다. 모든 테이블을 만든 뒤 이름이 안정적인 즉시 검사 FK를 `ALTER TABLE`로 추가한다. 이는 전역 최소 FK 분리 집합을 계산하지 않는다.

## 설계 관문

1. **원칙:** 이미 정의된 관계를 서버가 실제 DB 무결성으로 집행해 원칙 2·4를 실현한다. 문법이나 개발자의 선언을 늘리지 않는다.
2. **표현 범위:** 순환 `Ref<T>` facts를 배포할 수 있게 된다. 필드의 nullability, 읽기 정책, 전이 권한, FK의 즉시 검사 의미는 유지한다.
3. **서버 작성량:** 참조 순서를 우회하는 임시 SQL을 애플리케이션 개발자에게 요구하지 않는다. 제품 생성·마이그레이션이 같은 정형 DDL을 쓴다.
4. **최종 권한과 신뢰:** PostgreSQL FK가 존재하지 않는 ID를 거부한다. 마이그레이션은 기존 데이터까지 FK로 검사하며, 실패하면 트랜잭션을 되돌린다.
5. **생태계:** A/TS/Python 작성 형식의 facts와 SDK·wire 계약은 바뀌지 않는다. 비순환 DDL 문자열도 기존 그대로 둔다.
6. **중복 표현:** `Ref<T>`를 별도 타입이나 새 선언으로 바꾸지 않는다. SQL 생성 시에만 일부 FK의 배치 위치를 바꾼다.
7. **수단과 목적:** 막힌 위상정렬에서 미완료 참조 경로를 따라 반복 노드를 선택한다. 재귀나 전체 SCC 분석 없이 잔여 리소스 수 안에 순환 노드를 찾는다. 그 노드의 미생성 대상 FK만 분리하고, 이름은 resource·field의 digest로 결정해 마이그레이션 차이를 안정적으로 식별한다.
8. **OPEN:** FK를 지연 검사로 바꾸지 않는다. 양쪽 모두 필수인 순환은 빈 DB에서 단건 생성만으로 첫 행을 만들 수 없다. 그런 쓰기 API의 범위와 배치 생성 계약은 여기서 정하지 않는다.

## 검증 표면

- 기존 비순환 fixture의 DDL 지문과 inline `REFERENCES`가 바뀌지 않는다. 순환 밖의 의존 꼬리도 inline FK를 유지하며, 강제 생성된 순환 노드의 미생성 대상 FK만 후속 제약으로 분리한다.
- 실제 PostgreSQL에서 nullable 순환 행을 단계적으로 연결하고, 양방향 FK가 없는 ID를 SQLSTATE 23503으로 거부한다. AIP 읽기 정책도 기존대로 실행한다.
- 제품 초기화와 비순환→순환→비순환, 참조 대상 변경, 순환 리소스 삭제를 기존 행과 함께 마이그레이션한 뒤 preflight로 구조를 확인한다.
- [Saleor의 상품·기본 변형 관계](2026-10-07-oss-pattern-survey.md#실제-소스에서-추출한-규칙의-실행-대조)를 추출한 `spike-v3-write/tests/oss_product_variants.rs`는 순환 FK·유일성에 N:1·1:N 정책을 함께 적용하고, 전이 재시도와 부모 제약 실패의 상태·outbox rollback을 확인한다. 소유자·공개·활성화 정책은 이 probe의 규칙이다.
