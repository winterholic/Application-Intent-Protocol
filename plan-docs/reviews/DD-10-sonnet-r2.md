## 2. 새 모순, 임의 확정, 과잉 설계

| # | 내용 | 근거 |
|---|---|---|
| N-1 | **VV-1과 V1 범위(K1~K5)가 충돌.** VV-1은 근거를 "소유 컬럼이 행위자인 간선"으로 한정(v2:91). 그런데 K5(댓글 `isMine`, 행 필드와 actor 비교)는 간선이 아니라 행 필드이고(v2:33), 같은 문서가 K1~K5를 V1이 지원할 범위·82%로 센다(v2:36, 70, 130). VV-1 문자 그대로면 K5는 불가이고 커버율은 8/11(73%)이다 | v2:33, 36, 91, 130 |
| N-2 | **VV-1의 "정적 검사"가 V1에서는 의미 검사다.** V1은 서버 개발자가 식 문자열을 쓴다(v2:46~51). `owner == actor` 함의를 판정하려면 1라운드 H2·H5가 말한 영구 과제가 남는다. V5는 `owner` 선언으로 구조가 보장한다(v2:55~57). 문서는 "정적 검사로 확인한다"만 적고 V1/V5에 따라 달라진다는 점을 쓰지 않았다 | v2:91 vs 55~57 |
| N-3 | 예시가 열린 결정을 닫아 보인다. K2 예시 `where status = ACTIVE`(v2:49)는 F절이 "앱 개발자가 정할 것"이라 한 "활성 회원만인가"(v2:124)를 예시에서 이미 정한 모양이다. `개념 예시` 표기는 있으나 현행은 상태를 보지 않는다(v2:29) | v2:49, 124 |
| N-4 | VV-6의 "무효·만료는 인증 오류"가 viewer 값이 없는 공개 읽기에도 적용되는지 불명. 범위가 인증 전반이면 DD-10 소관이 아니다 | v2:96 |
| N-5 | 이탈 점검 2번이 PRINCIPLES §4 2번(표현 범위가 넓어지나 좁아지나)에 직접 답하지 않는다. "이름 고르기"는 좁히는 방향이다 | v2:139 |

임의 확정은 못 찾았다. 형태(V1/V5)와 DD-01 F1·DD-04 종속을 열어 두었고 창시자 신규 질문도 만들지 않았다(v2:124, 130). 과잉 설계도 없다. VV 7개는 1라운드 P0·P1에 1:1로 대응하고, VV-4는 PRINCIPLES §4 4번의 재진술이라 짧다.

## 4. 결론

**미합의 3개.**

1. P1-a: VV-1과 V1 범위(K5)의 모순(N-1)
2. P1-b: V1에서 VV-1 정적 검사가 성립하는 방식 미기재(N-2)
3. P1-c: 파생 값 종류 추론 미반영(P1-5)

세 개 모두 문서에 문장 몇 개를 더하면 닫히는 수정이다. 방향(단일 표면, V2 제외, VV-1~7 층 1)에는 이견이 없다. P0는 전부 반영됐고 남은 보안·캐시 쟁점은 없다. 확인 못함: 엔진이 없어 E2 공격 요청과 VV-1 정적 검사 가능성은 종이 분석이다. 아리아리 코드의 1라운드 사실(11개 필드)은 이번에 재열람하지 않고 1라운드 값을 인용했다.
