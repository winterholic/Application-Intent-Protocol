## 2. v2의 새 모순, 임의 확정, 과잉 설계

- 새 모순 없음. 행 번호 인용은 확인됨: 루프 4개 `lib.rs` 117~122행(문서의 116~123 범위 내), `workers` 89행(88행 근처), 구독 라우트 `http.rs` 49행, 확장 하드코딩 `dispatch.rs` 223·230행.
- 임의 확정: 없음. 결정 상태 "미결정"(3행, 141행). G의 "F1이 (가)이고 F3이 (나)라면 H가 유력"은 조건부 에이전트 의견으로 표기돼 있어 확정이 아니다. 다만 이탈 점검 152행 "(라)는 ... 하나를 정하는 편이 낫다"는 창시자 선택지를 에이전트가 깎는 어조다. 선택적 다듬기 대상.
- 표현 불일치(작음): F2 안내(132행)는 (가)(다)를 "구조로" 막는다고만 쓰지만, C.2 65행은 "자격증명을 안 주는 약속을 설정에서 지켜야 함"이라는 조건을 단다. 창시자는 F2만 읽으므로 "자격증명을 주지 않는 설정이 전제" 한 구절이 필요하다.
- 미표기 외부 주장: C.2 65행 "Rust 패닉이 호스트를 함께 죽일 수 있다", B.3 45행 "서버리스에서 루프가 돌 곳이 없다"에 `확인 필요`가 없다. 같은 표의 다른 외부 기술 주장에는 붙어 있어 일관성이 깨진다. 확인 못함: 두 주장의 공식 문서 근거(웹 미조사).
- 축 혼합: C.3 열 제목 "S·H·X"는 엔진 위치(S, H)와 확장 호출(X) 두 축을 한 열로 묶는다. 의미는 통하나 C.1과 어긋난다.
- 과잉 설계: 없음. 위협 모델, 비교표, E1~E5는 결정에 필요한 범위다.

## 3. F1~F3 평가

- 비전문가 응답 가능성: 가능하다. F1은 용어 풀이와 예시가 있고 (나)의 귀결(상시 서버 한 대)이 보인다. F2는 "바뀌는 것"을 같은 밀도로 적었다. F3은 2지선다이고 귀결 문장이 있다.
- 순서: F1(배포) -> F2(엔진 위치) -> F3(작성자)가 맞다. F1이 F2 선택지를 좁히는 관계와 일치한다. F3이 보안 구조를 가르므로 F2와 함께 본다는 점이 F3 본문에 한 줄 있으면 더 좋다(선택).
- F1(나)의 "상시 서버가 반드시 필요"는 일반 지식이며 `확인 필요` 표기가 없다(125행). 창시자 응답을 좌우하는 문장이라 표기를 권한다.
- 창시자 결정 범위: F1~F3 모두 제품 범위와 사용 경험이라 적절하다. 바인딩·FFI는 기술 제안으로 남겨 규칙 F절에 맞는다.

## 4. 잔여 수정 제안

- P1: 없음 (합의를 막는 항목 없음).
- P2-a: F2 132행에 "(가)(다)의 구조적 차단은 확장에 DB 자격증명을 주지 않는 설정이 전제" 추가.
- P2-b: 65행 패닉 주장과 45행 서버리스 주장에 `확인 필요` 표기, F1(나) 문장에도 표기.
- P2-c: C.2에 자원 상한(시간·메모리) 행 추가 또는 C.4-3에 메모리 상한·트랜잭션 참여·버전 식별 항목 추가 (DD-01 I6 146행의 "자원 상한"과 대응).
- P2-d: X(별도 서비스)를 비교하지 않는 이유 한 줄. 127.0.0.1 고정 바인드(`lib.rs` 126행) 한 줄.
- P2-e: D 103행 "E가 가장 직접"을 C.2와 같은 완화 표현으로, 152행 "하나를 정하는 편이 낫다"를 의견 표기로.

## 5. 결론

**에이전트 간 합의 도달.** R1의 P0 4건은 모두 반영됐고 P1은 일부만 부분 반영이지만, 남은 간극은 결정 구조를 바꾸지 않는 표현·보강 수준이다. v2에 새 모순과 창시자 미결정 사항의 임의 확정은 없다. 위 P2-a~e는 "선택적 다듬기"로 분류한다. F1~F3은 창시자 판단을 받을 수 있는 상태다. 외부 기술 주장(napi-rs, PyO3, 서버리스, 패닉 전파)은 이번에도 웹 확인을 하지 않았으므로 확인 필요로 남는다.
