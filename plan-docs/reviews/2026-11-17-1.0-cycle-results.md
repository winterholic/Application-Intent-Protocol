## 판정 기준과 출처

PR 상태는 2026-11-17에 직접 조회한 GitHub 결과를 기준으로 한다. 각 실행 수치는 연결된 Actions 원문 로그에서 확인했다. 상태 조회 뒤 진행 중인 실행은 기다리거나 다시 조회하지 않았다. 아래 `passed`는 해당 명령·job의 실제 통과 수이며 서로 다른 명령의 수를 합쳐 전체 테스트 수로 만들지 않았다.

Core PoC와 제품 Service는 서로 다른 실행 경로다. Core `.aipoc`의 parser/sema/IR/PG 결과는 Service `.aip`의 HTTP·PostgreSQL 결과를 대신하지 않는다. 생성 SDK, FlaskBB 원본 ORM, AIP Service HTTP/PG는 각각 적힌 경로에 대해서만 증거로 쓴다.

1. **PR #11·#12·#13은 기준 main에 포함되지 않았다.** 현재 direct `gh pr list` / `gh pr view` 결과에서 각각 OPEN이고 merge SHA가 없다. #11에는 cgroup `suite-first sample 2` 15/16 실패, #12는 Verify 진행 중, #13은 일부 release/core checks 진행 중이다. 병합 SHA와 확인하지 못한 통과 수는 `확인 필요`다.
2. **main의 release gate는 후속 세 PR을 포함하지 않는다.** [Run 44045763171](https://github.com/winterholic/Application-Intent-Protocol/actions/runs/44045763171)은 PR #9 merge SHA `02512a08e078812d6aeb3230c413e43472484be3`에서 실행되어 `ALL STEPS PASSED`를 기록했다. 새 clone/full regression, release package/smoke, upgrade/rollback 단계의 성공이다. 이 결과는 PR #11–#13의 코드나 후속 main SHA를 검증하지 않는다.
3. **worker probe와 WebSocket 안정성은 아직 닫히지 않았다.** 2초 timeout 원문이 실제로 남았고, 5초 candidate와 WebSocket 수명 검증은 PR #12 Verify 완료/merge 전이다. 원인과 복구를 확정하지 않고 출시 안정성 완료로 쓸 수 없다.
4. **P0 의미 fixture는 제한된 교집합이다.** Core와 Service의 특정 공통 expected 키는 실행했지만 9개 영역 전체 조합, 모든 policy/tenant/read matrix는 아니다. 이를 전체 제품 의미 동등성으로 표시하면 현재 증거를 넘는다. 출시 주장이 해당 범위를 포함한다면 그 범위는 별도 검증해야 한다.

### 결정이 필요한 정책 문제

- **공개 count의 rowRead 비상속:** 현재 제품 계약이다. `count`는 `sourceAccess`와 선언 `where`의 모집단을 세고 source `rows read`를 자동 적용하지 않는다. `sum/min/max`는 rowRead FILTER를 적용한다. PR #3은 이 차이를 실제 HTTP/PG 회귀와 `product/SDK.md` 계약에 남겼으며 기본 동작을 바꾸지 않았다.
- **fail-closed 기본값 전환 여부:** 공개 count가 숨은 행 변화에 반응하는 것을 보안 결함이라고 판정할지, 명시 `sourceAccess`/`where`/`callerFilter`를 요구하는 호환 계약으로 유지할지 정책 결정이 필요하다. FaceReview와 기존 넓은 집계 caller를 검토하지 않은 기본 전환은 집계 결과를 줄일 수 있다. 현재 실행은 공개 count 시나리오가 계약대로 동작함을 확인했을 뿐, 그 공개 범위가 제품 정책상 바람직한지 승인하지 않는다.
- 이 정책은 코드 검증 결과와 구분한다. 결정 전에는 현재 공개 count 결과를 `확인된 동작`으로 기록하고 안전성 승인이나 취약점 판정으로 확대하지 않는다.
