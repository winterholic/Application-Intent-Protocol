# DD-13 Sonnet 3라운드 합의 확인

> 대상: `../decisions/DD-13-client-sdk.md` v2.1(173줄). 비교: `DD-13-sonnet-r2.md` §5의 미합의 4개. 행 번호는 이번에 직접 읽은 것이다. 창시자 결정은 확정하지 않는다.

## 1. 미합의 4개 해소 여부

| # | 미합의 | 판정 | 근거 |
|---|---|---|---|
| 1 | 진단용 계약 산출물(N1) | 해소 | `:71`은 공개 계약만 생성 입력으로, `:73`은 진단 계약을 개발 환경 인증 개발자 전용 별도 산출물이며 프론트 번들에 안 들어간다고 적음. S6(`:98`)의 진단이 닫힌 필드를 아는 문제와 `:71`의 번들 비노출이 더는 충돌하지 않음. 두 항목 모두 [추천] 표기 |
| 2 | 응답 형식·오류 코드 의존(N2) | 해소 | `:75~77` C.2-1이 S3/S4/S8/S9/S12의 와이어 모양을 DD-08 후속 문서 확정 후로 미룸 |
| 3 | T2·C2 잠정 표기(N3) | 해소 | `:64` T2 "잠정: E2", `:87` C2 "잠정: E3", `:153` G에 둘 다 표기. 확정 문장은 없음 |
| 4 | F1·F2 장면·비용·기본값 | 해소 | F1 `:137` 모집 목록 장면, `:140` 비용, `:141` 기본값 (가). F2 `:144` 아리아리 사례, `:145` 시험 비용, `:147` 기본값 (가) |

## 2. 새 모순·임의 확정

- 새 모순은 발견하지 못했다. 변경 이력(`:172`)과 본문이 일치하고, D절(`:118`)의 "생성 타입은 공개 계약만"이 `:71`과 맞는다.
- 임의 확정은 없다. 상태는 "미결정"(`:3`, `:153`)이고 OI-P3·DD-01 F3 종속이 `:71`에 남아 있다. `:73`의 별도 진단 산출물은 [추천]일 뿐이다.

## 3. 결론

**에이전트 간 합의 도달.**

선택적 다듬기(합의를 막지 않음):
- E3(`:128`)를 "RQ 5.x에서 depends/changed 교집합으로 무효화를 표현할 수 있는가"처럼 구체화하면 실험 기준이 선다.
- `:8` 관련 목록에 DD-12, DD-01 F2 추가. `:101` 인용을 DD-01 I3에서 I1·I2로 정정(r1 7-12, r2 P2).
- F2 (다)를 고르면 첫 출시에 어댑터가 없어 S4·C2가 비는 점(r2 N4)을 `:147` 근처에 한 줄 주석.
- S6(`:98`)에서 `:73`의 진단 산출물을 가리키게 연결.
- F1 (가)의 "캐시 연결"은 비전문가에게 여전히 낯선 용어(장면이 있어 답은 가능).
- r2 P2 항목(7-10, 7-11, 7-14~7-16, 의제 14 미다룸 표)은 그대로 후속.
