## 2. 새 모순, 임의 확정, 과잉 설계

- **N1 (P1) 공개 계약 생성과 S6 진단이 서로 막는다.** `:71`은 T2가 "그 호출자에게 공개된" 필드만 싣는다고 한다. 그러면 닫힌 필드는 생성 타입에 없다. 반면 S6(`:92`)은 개발 도구가 "정확한 진단"을 보인다고 하고 DD-01 B.3(`DD-01:100`)은 "권한이 반영된 계약을 가진 빌드·개발 도구"만 정확한 진단을 준다고 한다. 어느 산출물이 그 진단용 계약을 갖는지(호출자 역할마다 생성물이 달라지는지, 개발 전용 별도 산출물인지)가 없다. r1 3.3에서 물은 "전체 vs 가시 계약" 중 후자를 택하면서 그 결과(역할별 SDK 빌드, 개발용 확장)를 적지 않았다. OI-P3를 임의로 닫지는 않았으므로 철학 위반은 아니고 정의 누락이다.
- **N2 (P1) 응답 형식·오류 체계 소유 문서가 없다.** S3(위반 처리), S4(태그), S12(오류 분류)는 응답 모양에 기댄다. DD-08:5는 "응답 형식, 오류 코드 체계, 멱등 키 전달, 인증 전달"을 후속으로 미뤘다. v2는 S8·S9·S12를 자기 책임으로 올리면서 이 선행 의존을 쓰지 않았다. 한 줄("S3/S4/S8/S9/S12의 와이어 형식은 DD-08 후속 응답 형식 문서를 따른다")이면 닫힌다.
- **N3 (P1) C2 추천이 E3 없이 서 있다.** 7-6 참고. 상태가 "미결정"이라 확정 위반은 아니다. 다만 DD-11:73이 확인 필요로 남긴 전제를 `:81`이 [추천]으로 올렸으므로 "E2·E3 전 잠정" 한 줄이 필요하다.
- **N4 (P2) F2 (다)와 G의 C2 추천이 어긋난다.** F2 (다) "프레임워크와 무관한 기본 라이브러리만"을 고르면 어댑터가 첫 출시에 없고, 그러면 S4(무효화, 어댑터 경유 `:90`)와 C2가 첫 출시에서 비어 있다. `:137` "어느 답이든 구조는 같다"는 구조는 맞지만 첫 출시에 어떤 S가 되는지는 답에 따라 달라진다.
- **임의 확정 점검:** 창시자 결정을 확정한 곳은 발견하지 못했다. 상태 "미결정"(`:3`, `:143`), 모든 선택이 [추천]. OI-P3·DD-01 F3 종속을 명시(`:71`). 이 항목은 합의에 걸림 없음.
- **과잉 설계:** S1~S13 13개는 많지만 S8~S13은 PoC(`tsgen.rs`)와 아리아리(`axiosInstance.ts`)에 실재하는 필요라 r1에서 요구한 것이다. 과잉은 아니다. S5만 조건부라 부담이 없다. 코어+어댑터+생성기+추론 4면(r1 6절 지적)은 `:156`이 "옮김"을 인정하나 지원 표면 수를 센 문장은 없다. P2.

## 3. F1·F2: 비전문가 창시자가 답할 수 있는가

방향은 맞다. 운영 규칙 F("제품 철학·UX에 영향을 주는 선택만")에 맞게 소유 범위와 지원 프레임워크가 질문으로 남았고, 캐시 도구 선택은 기술 제안으로 내려갔다(`:128`). 다만 문구는 아직 답하기 어렵다.

- **F1 (`:130~133`)**: "데이터 계층", "캐시 연결", "UI 컴포넌트"가 정의 없이 쓰인다. 운영 규칙 9(기술 개념을 AIP 사용 예시와 연결)와 4(시나리오 먼저)를 충족하지 못했다. 선택이 바뀌면 달라지는 장면이 없다. 예: "(가) 프론트 개발자가 모집 목록 화면의 로딩·에러 표시는 직접 만든다. (나) AIP가 목록·페이지 넘김 화면 조각을 같이 준다." 두 안의 비용(나는 AIP가 UI까지 책임져 유지보수 표면이 커짐)도 한 줄 필요하다. "답이 없으면 (가)로 진행"도 없다.
- **F2 (`:135~137`)**: "React(Next.js 포함)", "Vue"는 창시자에게 의미가 약하다. 아리아리 프론트가 React이고 React Query 5.66을 쓴다는 사실(`ariari-frontend/package.json:12`, `:22`)을 붙이면 (가)가 "지금 아리아리가 그대로 쓰는 환경"임이 보인다. 에이전트 의견 줄이 F1에는 있고 F2에는 없다. N4도 주석 필요.
- 결론: 두 질문 모두 창시자가 "알겠다"고 답하기엔 한 장면과 비용 한 줄이 부족하다. 구조 변경이 아니라 문구 보강이다(P1, 4절).

## 4. 잔여 수정 제안

### P0
없음. 창시자 철학과의 정면 충돌, 서버 권한 이양, 창시자 결정 확정은 없다.

### P1 (합의 전 닫을 것)
1. N1: `:71`에 "진단용 계약은 개발 도구 전용 산출물이거나 호출자 역할별 산출물이며, 어느 쪽인지는 OI-P3·DD-01 F3 후"를 한 줄 추가하고 S6에 어느 산출물이 진단을 갖는지 연결.
2. N2: C.4에 "S3/S4/S8/S9/S12는 응답 형식·오류 코드 체계(DD-08 후속)에 의존"을 한 줄 추가하고 `:8` 관련에 DD-12·DD-01 F2를 추가.
3. N3: G(`:143`)와 C.3 `[추천]` 옆에 "E2·E3 결과 전 잠정"을 쓰고 E3를 "RQ 5.x에서 depends/changed 교집합으로 무효화 대상을 지정할 수 있는가"로 구체화(RQ 술어 기반 무효화 API 존재는 **확인 필요**, 이번에도 웹 미확인).
4. F1·F2 문구 보강(3절): 장면 한 줄, 비용 한 줄, F2 에이전트 의견과 "답 없으면 (가)로 진행".

### P2 (후속 가능)

## 5. 결론

**미합의 4개.**
1. N1 공개 계약 생성과 S6 진단의 산출물 불일치
2. N2 응답 형식·오류 체계 선행 의존 미표기(S3/S4/S8/S9/S12)
3. N3 C2/T2 추천의 E2·E3 선행 잠정 표기 부재(r1 7-6 미반영)
4. F1·F2 문구가 비전문가 창시자에게 답하기 어려움(장면·비용·기본값 부재)

4개 모두 문장 단위 보강이며 구조·철학 변경은 필요 없다. 위 4개를 반영하면 "에이전트 간 합의 도달"로 본다. P2는 합의를 막지 않는다.
