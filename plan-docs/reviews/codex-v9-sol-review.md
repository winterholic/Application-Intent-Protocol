# V9 독립 검토와 반영

> 2026-10-04. Codex 메인 구현, `gpt-6-sol high` 설계·정확성 비평, `gpt-6-luna high` 인증 대조·테스트 작성. Claude는 이번 작업에 참여하지 않았다. 에이전트 합의는 창시자 승인이나 제품 전체 안전성 증명이 아니다.

| 검토 | 실제 근거 | 메인의 확인·반영 |
|---|---|---|
| Sol: 캐시 수명 최우선 | `cache.ts`의 무기한 hit, V6의 고정 NOW, DD-11 CI-5·DD-14 RE-6 | 서버 수명·단조 시계·왕복시간 차감, 현재 시각, 시간 의존 조회 미캐시 후보를 [V9 계획](../alignment/V9-cache-lifetime-plan.md)에 기록 |
| Sol: 같은 키 동시 호출 | 한 호출은 성공해도 다른 호출은 `WriteUnsettled`, pending 빈 배열을 인라인 재현 | 메인이 실패 테스트로 확인. 같은 키·같은 JSON의 진행 중 요청을 공유하고 다른 본문은 전송 전 거부 |
| Sol: JSON 직렬화 오류 | 전송 전 오류가 미확정 쓰기로 남을 수 있음 | BigInt 입력 반례 실패 후, 전송 전에 JSON 고정. 객체·오류 payload 변경도 원래 요청을 바꾸지 않음 |
| Sol: 늦은 응답의 보장 범위 | 수명 초과 응답은 미저장이나 rows는 한 번 반환 | 캐시 재사용 상한과 조회 시점 스냅샷을 구분. 서버가 읽기를 끝낼 때 이미 세션이 만료됐으면 응답 거부. 네트워크 이동 중 만료는 추가 재검증 보장 밖 |
| Sol: 짧은 토큰 테스트 | 1초 TTL은 초 단위 내림·Node 시작 지연에 취약 | 토큰 2초, 발급 직후 Node 시작, 2100ms 대기. 테스트 준비가 1초 이상 지연되는 환경은 추가 handshake 개선 여지 |
| Luna: V8 인증 대조 | 단위·실제 HTTP/PG 검증을 각각 실행. 인증 우회는 찾지 못함 | 확인 범위만 기록. `iat` 미검증을 신뢰 발급기 범위의 인증 우회로 과장하지 않음 |
| Luna: 인증 입력 상한 | 헤더 라인·총량·Bearer 길이 제한 부재 | Luna가 본문 전 거부 테스트를 작성, 세 초과 사례 실패. 메인이 8KiB/16KiB/1KiB 실험 상한을 적용한 후 통과 |
| Luna: V9 HTTP/PG 대조 | 알림 캐시·다른 연결 쓰기·토큰 만료·모집 미캐시 테스트 작성 | 메인이 실제 DB 권한 회수 fixture와 DB 최종 상태 단언을 추가하고 실행 |

최종 Sol 검토에서는 V9의 세션 수명·왕복시간 차감·현재 Ctx의 now 바인딩 탐지에 추가 반례를 찾지 못했다. 최종 독립 검토는 코드 대조이며 DB 테스트는 메인/Luna 실행이다. 검증 명령과 보장 한계는 [V9 결과](../alignment/V9-cache-lifetime-results.md)를 따른다.
