## 2. 새 모순·미결정 사항 임의 확정 점검

**새로운 중대한 모순은 없고, 창시자 미결정 사항도 임의로 확정하지 않았다.** 문서 상태는 계속 `미결정`이며(`DD-01:3`), 실행 시점·작성 방식·자연어 문법화는 각각 DD-03·04·05로 남겼다(`:4`). 저장된 조회와 확장 읽기도 `[추천]` 및 F4 확인 전임을 표시했다(`:115-117`).

v2의 다섯 이견도 해소됐다.

- 층 1은 의미·안전 불변식, 층 2는 조건부 구현 수단으로 분리됐다(`DD-01:136-167`).
- preset 권한은 인덱스가 아니라 명시적 필드 목록에서 나온다(`:150-155`).
- 공개 집계와 비공개 간선 행이 별도 capability로 분리됐다(`:76-81`, `:93-95`).
- saved read와 extension read가 분리됐다(`:115-117`).
- 추천 근거가 줄 수에서 실제 서버 변경·중복·계약 변경으로 바뀌었다(`:194`, `:224`).

### 선택적 다듬기

I2의 “집계에도 간선 정책 적용”(`DD-01:141`)과 I7의 공개 집계(`:146`)는 B.3 설명으로 의미가 풀려 있지만, 문장만 떼어 읽으면 긴장해 보일 수 있다. I2를 “호출자가 조합하는 관계·집계 경로”로 한정하고, I7의 서버가 명시적으로 비식별 결과를 공개하는 경우를 교차 참조하면 더 선명하다. 이는 설계 이견이나 합의 차단 사유가 아니다.

## 3. F1~F4 문장 검토

| 질문 | 판정 | 이유 |
|---|---|---|
| F1 읽기 기본 모델 | **답할 수 있음** | “새 화면”, “서버 API 추가 없이 조합”, “서버가 최종 판단”이라는 사용자 경험으로 묻고, 거절 시 대안도 평이하게 설명한다(`DD-01:203-205`). |
| F2 새 필드 기본 비공개 | **답할 수 있음** | 안전 기본값과 선언량 비용, 자동 공개 시 보안 책임을 직접 대비한다(`DD-01:207-209`). |
| F3 첫 출시 호출자 | **답할 수 있음** | 자사 프론트부터 불특정 서드파티까지 구체적인 대상과 단계 도입 가능성을 보여 준다(`DD-01:211-213`). |
| F4 특수 조회 확장 | **답할 수 있음** | `타입·권한·비용 한도`가 있는 JS/Python 확장이라는 안전 경계를 제시하고, 표준 조합과 중복하지 않는 규칙을 함께 설명한다(`DD-01:215-216`). |

네 질문 모두 제품 철학·지원 범위·보안 기본값에 관한 선택이며, 내부 구현 세부를 창시자에게 떠넘기지 않는다. 비전문가도 앞의 실제 아리아리 예시와 함께 읽으면 선택의 결과를 판단할 수 있는 수준이다.

## 4. 결론

**에이전트 간 합의 도달. 남은 이견 0개.** 수정 대안 2의 상위 방향, I1~I7의 안전 불변식, 가장 단순한 구현 우선, 명시적 preset, 공개 집계와 간선 행의 분리, saved read와 extension read의 구분, E2·E3 검증 기준, F1~F4 문장에 동의한다.

이 합의는 창시자 승인이나 설계 확정을 뜻하지 않는다. DD-01은 적절하게 `미결정`이며, 창시자가 F1~F4를 판단하고 E1~E4의 증거가 나온 뒤 추천 유지 여부를 다시 평가해야 한다.
