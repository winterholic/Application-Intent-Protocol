# B. 결정 상태 재분류

> 기준: [창시자 통합 지침](../sources/founder-integrated-directive-2026-10-03.md) §9~11·14·15. 2026-10-03.
> 원문 표식과 아래 분류는 다른 축이다. [FOUNDER]가 있어도 그 항목의 모든 기술 사양이 승인된 것은 아니다.
> 이 문서는 질문의 처리 상태 정본이다. 구체적인 기술 대안은 기존 DD와 [C](C-syntax-proposal.md), 검증 과제는 [E](E-technical-risks.md)를 따른다.

## 1. 분류 기준

| 분류 | 적용 기준 | 다음 행동 |
|---|---|---|
| 창시자 결정 확인 | 원문에서 목적·책임·제품 구조를 직접 밝힘 | 해당 사실을 재질문하지 않는다. 세부 구현은 별도로 검증 |
| 방향은 확인되었으나 상세 설계 필요 | [DIRECTION] 또는 확인된 목적과 미정 세부가 함께 있음 | 설계안을 작성하고 반례·비용을 비교 |
| 기술적 검증으로 해결 가능 | 실험으로 표현력·안전성·비용을 비교할 수 있음 | 먼저 실험. 실험 결과를 창시자 승인으로 바꾸지 않음 |
| 창시자의 추가 판단 필요 | 출시 범위·가치 판단·개발 경험·라이선스에 영향 | 비교 가능한 결과가 준비된 뒤에만 묻는다 |

여러 성격을 가진 항목은 현재 남은 일의 분류를 표시하고, 이미 답한 부분을 따로 기록했다. 상세 설계가 남아 있다는 이유로 창시자 답 자체를 미결정으로 되돌리지 않는다.

## 6. 새로 확인된 별도 기준

- 선택적 개발 지원 검증은 공식 제공 대상이다. 서버 타입·권한·무결성·자원 검증은 필수다. 같은 검사 알고리즘을 공유하더라도 선택적 CLI를 껐다고 필수 단계가 꺼져서는 안 된다.
- 오픈소스와 외부 기여 환영은 확인됐다. 라이선스는 아직 미정이며 설치·배포 설계가 특정 라이선스 채택을 뜻하지 않는다.
- 기술적 이견은 [E](E-technical-risks.md)에서 검증 과제로 관리한다. 기존 Claude/Codex 합의를 새 지침 검토 결과로 재사용하지 않는다.
