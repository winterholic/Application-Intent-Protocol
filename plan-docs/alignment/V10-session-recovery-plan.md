# V10. 세션 갱신과 미확정 쓰기 복구 계획

> 상태: 기술 후보. 제품 로그인·갱신 토큰 저장 정책을 확정하지 않는다. [V9](V9-cache-lifetime-results.md)의 고정 토큰과 수동 pending 이관을 보완하는 독립 실험이다.

## 설계 관문

1. 원칙 1·2·4·6: 앱마다 작성하는 토큰 교체·멱등 복구를 공통 SDK가 흡수한다. 자동 재송신은 최초 actor·키·JSON을 유지해야 한다.
2. read/apply의 호출자 표현 범위는 유지한다. 인증 갱신 때문에 업무별 서버 계약을 추가하지 않는다.
3. 서버 공통 `/session`과 SDK `replaceSession(token)`으로 반복 구현을 줄인다. 실제 신원 확인은 기존 로그인 제공자의 책임이다.
4. 최초 쓰기 전 서버가 토큰의 principal을 확인한다. 새 토큰도 서버가 확인하고 같은 actor일 때만 교체한다. principal 확인은 현재 업무 권한의 증명이 아니며 매 실행 정책을 다시 평가한다.
5. Rust·TS 경로를 재사용한다. Python 확장 ABI는 유지하고 Python 클라이언트 동등성은 별도 검증 대상으로 둔다.
6. 업무 표현이나 actor별 복구 저장소를 새로 만들지 않는다. 다른 계정은 별도 연결을 사용하는 후보이며 기존 연결의 pending을 폐기하지 않는다.
7. 실행·응답 유실·갱신 경합을 테스트한다. 내부 IR 정교화로 목적을 대체하지 않는다.
8. 같은 actor 갱신은 기술 후보다. OIDC·Cookie/CSRF·tenant·다중 서버·브라우저 재시작 영속 복구·익명에서 회원으로 pending 이관은 채택하지 않는다.

## 상태와 불변식

- `/session {}`은 서명·만료 검증 후 DB 접근 없이 actorId(10진 문자열)와 잔여 수명을 반환한다. 요청 본문에 actor를 지정할 수 없다.
- 미확정 쓰기는 서버가 확인한 principal, 키, 최초 JSON에 귀속한다. SDK가 처음 전송할 때부터 추적하고, 확정 응답이 없으면 보존한다.
- 캐시·진행 중 요청은 인증 세대에 귀속한다. 토큰 교체 전 검증 실패나 다른 actor 응답이면 원 상태를 유지한다.
- 같은 principal 갱신은 세대를 증가시키고 캐시를 비운다. 이미 진행 중인 키도 새 세대에서 같은 JSON으로 재송신할 수 있으며 서버 멱등 저장소가 중복 효과를 막는다.
- 이전 세대 응답은 새 세대의 성공/실패 근거로 채택하지 않는다. 새 세대가 같은 키의 결과를 이미 확정했다면 그 확인된 결과를 공유한다.
- 세대별 동일 키 요청을 공유한다. 이전 세대의 종료가 새 세대의 요청을 지우지 않는다. 동시 토큰 교체는 직렬화한다.
- 익명 principal은 개인 식별자가 아니다. 익명 pending을 로그인 사용자에게 자동 이관하지 않는다.
- 기존 [V8 r9](../reviews/codex-v8-r9.md)의 익명 sentinel 충돌을 반례로 포함한다. 멱등 저장소 scope를 인증 actor와 익명으로 구조적으로 분리해 actor=-1도 익명 키를 재생하지 못하게 한다. ID 도메인을 임의로 축소하지 않는다.

## 검증

먼저 실패 사례를 고정한다. 같은 사용자 갱신·만료 뒤 복구·다른 사용자 거부·위조 토큰·이전 read/write의 늦은 완료·동시 갱신·캐시 폐기·중복 실행 방지를 Node와 실제 HTTP/PG에서 확인한다. 기존 V5/V6/V8/V9 회귀, strict tsc, Rust fmt/clippy, 문서 링크 대조를 실행한다.
