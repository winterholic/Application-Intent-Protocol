# V11. 선택적 개발 검사와 필수 실행 검사 분리

> 상태: 기술 후보. [통합 지침](../sources/founder-integrated-directive-2026-10-03.md)의 원칙 5·6과 [C B.8·SY-5·SY-6](C-syntax-proposal.md), [E RK-07](E-technical-risks.md)를 실행으로 대조한다. 최종 문법·기본 lint·AI 의미 검사 채택은 결정하지 않는다.

## 설계 관문

1. 원칙 4·5·6을 실현한다. 설명을 강제하거나 개발 조언을 서버 실행 승인 조건으로 만들면 원칙 5와 충돌하므로 분리한다.
2. 호출자 read/apply 표현 범위는 유지한다. 개발 검사 옵션은 서버 정의를 다루는 로컬 도구에만 있고 runtime 요청의 우회 옵션이 아니다.
3. 서버에 새로운 필수 선언은 없다. 기존 V1 fixture의 docs가 없어도 실행 가능하고, 개발 조언 한 가지는 선택적으로 실행한다.
4. V1의 구조·타입 확인과 V2의 매 요청 권한·타입·비용 검사는 필수로 유지한다. docs의 권한 주장은 신뢰하지 않는다. 개발 검사 off/on에서 같은 거부·행 가시성을 확인한다.
5. 기존 A·E-TS·E-Py·H-TS·H-Py load_str 출력과 V5 계약 생성을 재사용한다. 새 host 실행이나 별도 문법·IR은 만들지 않는다.
6. 조언은 이미 선언된 predicate의 직접 참조 부재 한 가지로 제한한다. 반복 작성 방식을 늘리지 않고 옵션은 기본 off·명시 on·알 수 없는 키 거부로 검증한다.
7. 출력의 execution/metadata/spans를 보존하고 조언을 별도 반환한다. 근거는 실행 facts·SQL·DB 결과·생성 TS의 대조이며 자연어에 대한 LLM 판정을 넣지 않는다.
8. 제품 기본 lint, 출시 언어 기능 동등성, source map 전체, 인간이 의도한 설명 소속/진실성, 최종 API는 확정하지 않는다. 본 `crates/`는 보존한다.

## 최소 실행 범위

독립 `spikes/spike-v11-dev-checks/`에서 옵션을 검증한 뒤 항상 V1 구조·의미 검사를 실행한다. 요청된 경우에만 직접 참조되지 않는 predicate 조언을 실행한다. 오류와 advisory를 다른 출력으로 다루고 advisory가 있어도 정상 계약 생성/계획/실행을 막지 않는다.

- docs 없음·변경·다른 resource로 이동·빈 줄 이동: execution digest와 V5 생성 TS는 동일, metadata anchor/source span만 해당 변화에 맞게 변경.
- 5개 작성 형식과 option 기본 off/on: 기존 실행 facts 동일. 일부러 추가한 미참조 predicate는 off에서 조언 없음, on에서 정확한 anchor의 조언.
- 모르는 옵션·잘못된 옵션 타입·모르는 docs 키는 조용히 무시하지 않고 구조 오류. 필수 정의 타입/기호 오류도 off/on에서 거부.
- raw JSON 읽기의 비공개 필드·필터·잘못된 값·rows/depth/cost 오류를 off/on에서 동일하게 거부한다.
- 실제 PG에서 학교/회원별 행 가시성과 관리자 메모 마스킹을 off/on·docs 변경 전후에 대조한다. docs에 '모두 읽을 수 있음'을 적어도 권한이 넓어지지 않는다.

미참조 조언은 직접 호출 관계의 국소 검사다. 모든 미도달 코드나 사용자의 업무 의도를 판정한다고 주장하지 않는다. 개발 조언을 끄는 것과 필수 parser/sema/planner 검사를 끄는 것을 구분한다.

## 검증 방식

동작 실패를 먼저 확인하고 구현한다. cargo test, fmt, clippy로 독립 spike를 검증한다. V1/V2/V5 회귀와 문서 구조 검사를 연결하고, 선택적 검사 경로를 고장 주입했을 때 대조 테스트가 실패하는지도 확인한다. 서버 런타임이 개발 조언 결과를 입력받지 않는 경계를 실제 계획·실행으로 대조한다.
