# T07. 보안: 인증, 인가, 위협 모델

> **2026-10-03 기준 정본:** [창시자 통합 지침](../sources/founder-integrated-directive-2026-10-03.md)과 [B 결정 상태 재분류](../alignment/B-decision-reclassification.md)가 우선한다. 아래 초안·후보·미정·자료 요청은 이전 기준의 기록이며 전체 승인으로 보지 않는다. 이전 기준의 질문이 B에서 해결·대체된 경우 재질문하지 않는다.
> 이전 기준의 초안 상태: v0 (2026-10-03). 기준 원문: PART I §2 보안 철학, 의제 5. 당시 보안 책임 변경을 창시자 승인 사항으로 표시했으며, 현재 원칙과 기술 검증 범위는 B를 따른다.
> **관련 기술 기록:** `../decisions/DD-01-read-composition.md`, `../decisions/DD-02-write-scope.md` — 기존 리뷰는 이전 지침의 검토 이력이다. 현재 결정 상태는 [B](../alignment/B-decision-reclassification.md)를 따른다.

## 1. 설계 관문

| # | 답 |
|---|---|
| 1 원칙 | 보안(서버 최종 통제)을 실현. 작동 모델과 긴장 |
| 2 호출자 범위 | 범위를 좁혀서 안전을 얻지 않는다. 자유는 넓히고 판단은 서버가 매번 |
| 3 서버 작성량 | 정책 선언이 서버 작성량의 핵심이 된다. 정책을 짧고 정확하게 쓸 수 있어야 한다 |
| 4 서버 권한 | 이 문서가 답한다 |
| 5~8 | 해당 정의 문서에 따른다 |

## 2. 원문의 보안 원칙과 설계 대응

| 원문 원칙 | 설계 대응 (초안) | 기존 PoC |
|---|---|---|
| 표현 자유와 실행 권한은 별개 | 요청은 원하는 것만 담고 권한·계획은 담지 않는다 | 해당(요청에 권한 정보 없음) |
| 요청한다고 모두 허용하지 않는다 | 노출 기본 거부 + 매 요청 정책 평가 | 선언 단위로 구현 |
| 인증·인가는 서버가 최종 결정 | 토큰 검증과 정책 평가는 Runtime에서만 | HMAC 토큰, `allow` |
| 데이터 접근 범위와 동작은 서버 정책을 따른다 | 행 가시성, 필드 가시성, 동작별 정책 | 구현 |
| 테넌트 격리와 무결성 | 테넌트 필터 자동 삽입, DB 수준 고정, 제약 | 구현(트리거 고정) |
| 호출자가 서버 내부 구현을 제어 못함 | 원시 SQL·코드·계획 힌트 금지 | 해당 |
| 조합 요청이 권한 우회로 이어지지 않음 | 조합된 각 부분과 전체에 같은 정책. 숨은 필드로 필터·정렬·집계 금지 | **조합 경로가 없어 미검증** |
| 비용, 깊이, 복잡도, 자원 통제 | 실행 전 비용 상한 검사, 실행 중 시간·행 수 제한 | 선언 쿼리의 무제한 목록 경고(W403)만 |

## 3. 조합 요청에서 새로 생기는 위협 (위협 모델 초안)

T01 §7 실험에서 선택지마다 아래 공격을 만들어 막히는지 본다.

| ID | 위협 | 예 | 막는 수단 후보 |
|---|---|---|---|
| TH1 | 숨은 필드 추측 | 볼 수 없는 `salary`로 `where salary > 1000` 필터해 결과 유무로 값 추측 | 필터·정렬·집계에 쓰는 필드도 필드 가시성 검사 |
| TH2 | 관계 경유 우회 | 볼 수 있는 A에서 관계를 타고 볼 수 없는 B의 필드 읽기 | 관계 탐색 단계마다 대상 리소스 정책 평가 |
| TH3 | 집계로 개별 값 유출 | 대상이 1건이 되도록 좁힌 뒤 `sum`으로 값 얻기 | 집계 허용 리소스·필드 명시, 최소 집단 크기 후보 |
| TH4 | 존재 노출 | 거부와 부재를 다르게 응답 | 보이지 않는 행은 부재로 응답 |
| TH5 | 비용 공격 | 깊은 관계 중첩, 큰 페이지, 정렬 없는 큰 스캔 | 깊이·행 수·조인 수·시간 상한, 인덱스 없는 정렬·필터 거부 후보 |
| TH6 | 테넌트 교차 | 관계를 타고 다른 테넌트 행에 닿기 | 테넌트 필터를 모든 스캔에 자동 삽입 |
| TH7 | 쓰기 필드 확대 | 수정 요청에 허용 안 된 필드(`role`) 끼우기 | 필드 단위 쓰기 정책, 노출 안 된 필드 거부 |
| TH8 | 상태 전이 우회 | 단순 쓰기로 상태를 직접 바꿔 승인 흐름 건너뛰기 | 상태 필드는 생명주기 규칙으로만 변경 |
| TH9 | 조합 쓰기의 부분 실패 악용 | 묶음 중 일부만 성공시켜 불변식 깨기 | 묶음 단위 트랜잭션, 불변식은 DB 강제 |
| TH10 | 대리 접속 남용 | 대리 세션으로 권한 상승 | 매 호출 세션 재확인(PoC 구현) |

## 4. 기존 PoC에서 가져갈 것

정책 평가, 가시성 기반 부재 응답, 필드 가시성, 테넌트 고정, 대리 접속 재확인, 멱등, 감사 기록, SSRF·DNS rebinding 차단. 모두 선언 Intent 기준으로 검증됐다. 조합 요청 모델에서 다시 검증해야 한다(원문 의제 5).

## 5. 열린 것

- 인증 체계(외부 OIDC 연동 범위). 현재 실제 제공자 없음
- 정책 문법(T02 결정 뒤)
- 비용 상한의 기본값과 재정의 방식
