## 2. 확인된 기준

- 설명을 특정 선언에 귀속시킬 공식 문법 위치를 제공한다. 작성은 선택 사항이다(통합 지침 §6.1~6.2).
- 자연어 내용의 참·거짓이나 의미 정합성 검증은 필수 요구가 아니다. 설명은 실행 계약과 분리되고, 실행 권한이나 보안 정책의 근거가 되지 않는다(§6.3, B 질문 11~13).
- 별도의 선택적 개발 검증 계층은 제공하되, 서버의 필수 실행 안전성 검증과 분리한다(통합 지침 §7, B §6).

## 3. 후속 설계·검증 항목

1. 메타데이터 키와 값의 타입·소속을 어떻게 정의하나
2. 메타데이터를 어떤 개발 도구 출력이나 공개 계약에 포함하나
3. 값의 타입·소속 점검과 자연어 내용의 의미 판정을 어떻게 구분하나
4. 개발 검사의 실행 여부와 서버 필수 안전성 검사를 어떻게 독립시키나

이 항목들은 기술 설계다. 자연어 의미 자체나 예시를 창시자에게 다시 요청하는 전제가 아니다.

## 4. 이전 탐색 후보 (기록 보존; 현재 승인안 아님)

아래 N1~N7은 이전 초안에서 탐색한 후보 기록이다. 전체가 승인된 것은 아니다. 자연어 설명에 실행 효과나 권한 의미를 부여하는 N2·N3·N7식 해석은 현재 기준에서 채택하지 않는다. 실행 조건·사후조건·타입 계약은 설명 문장이 아니라 별도 정형 계약으로 정의해야 한다.

| 후보 | 예시 방향 | 실행 영향 | 생각해 볼 점 |
|---|---|---|---|
| N1 목적의 구조화 | 리소스·동작마다 "왜 있는가"를 정해진 칸에 쓴다 | 없음(탐색·문서) | 주석과 무엇이 다른지 증명해야 한다. 기계가 읽는 위치와 형식이 정해져 있다는 점이 차이 |
| N2 전제조건의 구조화 | "이 동작은 회원만, 모집 중일 때만"을 문장 대신 구조로 | 이전 후보의 실행 영향 제안은 현재 기준에서 기각. 설명은 권한 정책이 아님 | 정책·상태 조건은 별도 실행 계약으로 둔다 |
| N3 기대 결과의 구조화 | "끝나면 지원자 수가 1 늘고 알림이 간다" | 설명에는 실행 영향 없음. 별도 개발 검사는 선택 사항 | 설명과 실행 사실은 분리한다 |
| N4 도메인 의미 표현 | "정원", "모집 기간" 같은 도메인 개념을 타입·이름으로 | 타입·계약은 실행 facts, 자연어 metadata는 설명만 | 설명 문장을 타입 정의의 대체물로 쓰지 않는다 |
| N5 AI 탐색 구조 | Index → Contract → Implementation 순서로 AI가 점진 탐색 | 없음 | 원문 §6 "확정 파일 포맷 아님". 문서화 표준과 연결 |
| N6 실행 계약과 설명 정보의 분리 | 같은 블록 안에서 "실행되는 것"과 "설명하는 것"을 구분된 칸으로 | 칸에 따라 | 원문이 직접 제시한 후보 |
| N7 문법 자체를 자연어에 가깝게 | 선언을 자연어 문장 구조로 | 자연어를 실행 규칙으로 해석하는 방식은 현재 기준에서 기각 | 정형 계약과 선택적 설명을 구분한다 |

## 5. 설명과 실행 계약의 구분

- 설명 메타데이터는 선언에 귀속되는 선택적 문서화다. 문법 위치와 공개 형식은 설계할 수 있지만 작성은 강제하지 않는다.
- 타입·권한·정책·무결성·자원·실행 효과는 필수 계약 facts다. 이를 자연어 설명으로 대체하지 않는다.
- 개발 검사는 선택적으로 제공한다. 검사를 끄더라도 서버의 필수 실행 검증은 유지한다.

## 6. 이전 기준의 창시자 입력 요청 (해제됨)

이전 초안은 N1~N7의 방향과 예시 문장을 요청했으나, 이 요청은 현재 선행 조건이 아니다. 통합 지침 §6~7과 B 질문 11~13·Q5가 기준이며, 정확한 키·타입·소속·공개 범위와 검사 계층을 설계한다.
