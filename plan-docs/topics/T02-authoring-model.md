## 2. 원문이 확정한 것과 열어 둔 것

| 구분 | 내용 |
|---|---|
| 합의된 방향 | 독립적인 표현 체계를 가진다 / 선언 블록 중심 / resource, query, command 등 표준 구성 요소 / 조건문, 반복문, 함수, 표현식 같은 제어 흐름 지원을 논의 / A형 문법 선호, B형은 Java 같다는 이유로 비선호 / 기본값 우선, 명시적 재정의 / 개발자가 Rust를 쓰지 않는다 |
| 열린 것 | 고유 문법이 독립 소스 파일 언어인지, JS/Python 안의 API인지, 둘 다인지 / `.aip`를 유지할지 폐기할지(둘 다 단정 금지) / 여러 작성 방식을 둘 때 canonical 표현과 우선순위 |
| 이전 기준의 확인 요청 | A형·B형 문법의 원본 예시를 찾지 못해 대화 기록을 요청했던 흔적이다. B Q3에 따라 예시 부재는 착수 장애가 아니며, 정확한 문법은 독립 검토·비교 대상으로 둔다. |

`../docs/DECISIONS.md` D-R6(`.aip`를 정본 작성 언어로 삼지 않는다, Rejected)은 이전 기록이다. AIP 고유의 정형 표현 체계는 유지하고 독립 `.aip` 파일 여부는 B Q2·Q3 기준으로 기술 비교한다.

## 3. 원문의 세 안

| 축 | A. 독립 `.aip` DSL 중심 | B. TS/Python API 중심 | C. 독립 의미 모델 + 여러 공식 작성 방식 |
|---|---|---|---|
| JS/Python 생태계 | 별도 파일·도구. 에디터 지원, 패키지, 린트를 새로 만들어야 한다 | 그대로 쓴다. npm, pip, 타입 검사, 에디터 | 작성 방식마다 다르다 |
| 선언 블록 문법 | 가장 자연스럽다. 문법을 마음대로 설계 | TS/Python 문법 안에서 흉내. 객체 리터럴, 빌더, 데코레이터 중 고른다 | 둘 다 가능 |
| 한 의도 한 표현 | 문법이 강제할 수 있어 가장 강하다 | 가장 약하다. 린트·검증 규칙으로 좁혀야 한다 | 작성 방식 사이에 표현 차이가 생긴다. canonical 표현과 우선순위가 반드시 필요 |
| AI 작성 편의 | AI가 학습한 적 없는 문법. 문서와 예제로 가르쳐야 한다. 대신 선택지가 적다 | AI가 이미 잘 쓰는 언어. 대신 "어떻게 쓸까" 선택지가 많다 | 작성 방식 선택이라는 선택지가 하나 더 생긴다 |
| 확장(JS/Python) 연결 | 문법 경계를 넘어야 한다 | 같은 파일 안에서 자연스럽다 | 방식에 따라 |
| 기존 자산 | `aip-syntax`, `spec/grammar.md`, 예제 4개 그대로 | 파서 대신 TS/Python 프런트엔드를 새로 만든다. 의미 검증 이하는 재사용 가능 | 둘 다 유지 비용 |
| 구현 난이도 | 언어 도구 일체(파서, LSP, 포매터) | TS 타입 수준 설계와 Python 대응. 두 언어에서 같은 의미 보장 | 가장 크다 |

## 4. 생각해 볼 조합 `[선택지]`

| 조합 | 내용 | 생각해 볼 점 |
|---|---|---|
| C-정본 하나 | 의미 모델 하나 + TS를 정본 작성 방식으로, Python은 같은 의미의 공식 대응, `.aip`는 정규 출력(사람·AI가 읽는 표기, 디버그·diff) | 고유 문법을 "쓰는 언어"가 아니라 "읽는 표기"로 남긴다. 원문 "고유 문법을 제거하지 마라"와 맞는지 확인 필요 |
| C-블록 내장 | TS/Python 안에 선언 블록을 쓰는 정형 형식(예: 태그드 템플릿, 전용 파일 확장자 + 언어 플러그인)을 두고 같은 패키지로 배포 | 선언 블록 문법의 장점을 살리면서 생태계 안에 둔다. 에디터·타입 연동이 어렵다 |
| A+확장 | `.aip`를 정본으로 유지하고 확장만 TS/Python | 이전 후보는 창시자 재확인을 조건으로 적었다. 현재 문법 형식 판단은 B Q2·Q3의 기술 비교를 따른다. |

## 5. 어느 안이든 필요한 것 `[추천]`

1. 작성 방식이 여럿이면 **canonical 표현을 하나** 정하고, 나머지는 그것으로 정확히 변환된다(같은 의미 → 같은 결과물).
2. TS/Python 쪽은 허용하는 모양을 좁히고, 벗어난 모양은 검증기가 구조화된 오류로 잡는다.
3. 프로젝트 구조와 정의 위치를 고정한다(AI First 7번).
4. 제어 흐름(조건, 반복, 함수)의 범위를 정한다. 표준 문법 안의 제어 흐름과 확장(JS/Python 함수)의 경계는 T09와 함께 정한다.
