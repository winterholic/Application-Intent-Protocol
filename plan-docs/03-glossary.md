# 03. 용어 정의

> 상태: 통합 지침 반영 (2026-10-03). SPR 책임과 선택적 metadata 목적은 [창시자 기준](sources/founder-integrated-directive-2026-10-03.md)이다. Envelope·세부 Intent 분류·패키지/문법 용어는 기술 제안이다.

용어를 먼저 고정하는 이유: 지난 문서들에서 "Intent"가 "서버가 이름 붙인 함수"라는 뜻으로 굳으면서 호출자 중심 모델이 사라졌다. 같은 단어가 문서마다 다른 뜻이면 설계가 다시 흐려진다.

## 1. 핵심 용어

| 용어 | 정의 (초안) | 지난 문서와의 차이 |
|---|---|---|
| **호출자 (Caller)** | AIP 서버에 요청을 보내는 주체. 브라우저·앱 프론트엔드가 기본이고, 다른 서비스나 AI 에이전트일 수도 있다 | 지난 문서는 "클라이언트"로 쓰며 생성된 TS 클라이언트만 상정 |
| **행위자 (Actor)** | 요청의 권한 판단 대상인 사용자나 시스템 주체. 호출자와 다를 수 있다(예: 대리 접속) | 같음 |
| **Intent** | 호출자가 원하는 결과나 동작을 AIP의 표준 형식으로 표현한 구조화된 요청 하나. 문법, 타입, 계약을 갖춘다. 자연어 명령이 아니다 | 지난 구현은 "서버에 선언된 query/command 이름 + 입력". 그 형태는 Intent의 한 종류(선언 Intent)일 뿐이다 |
| **조합 Intent** | 호출자가 계약 범위 안에서 데이터 선택, 관계, 조건, 정렬, 페이지, 동작을 조합해 만든 Intent. 서버에 같은 이름의 정의가 없어도 된다 | 지난 구현에 없음(D-P8로 금지, 지금은 D-R5로 기각) |
| **선언 Intent (Command 포함)** | 서버 쪽 정의에 이름으로 선언된 동작. 비즈니스 규칙이 몰린 쓰기의 후보 | 지난 구현의 유일한 형태 |
| **서버 계약 (Contract)** | 호출자가 요청할 수 있는 범위를 기계가 읽을 수 있게 적은 것. 노출된 리소스, 필드, 관계, 동작, 타입, 오류 | 지난 구현은 선언 intent 목록(`/aip/describe`) |
| **경계 (Envelope)** | 서버가 조합 Intent에 거는 한계. 정책(누가, 무엇을), 비용 상한(깊이, 행 수, 조인 수, 시간), 허용 연산 | 새 용어 |
| **정책 (Policy)** | 실행 가능 여부를 정하는 서버 규칙. 허용(allow), 행 가시성, 필드 가시성, 테넌트, 상태 조건 | 지난 구현의 `allow`, `visible`, `tenant` 등 |
| **정의 (Definition)** | 애플리케이션 개발자가 서버 쪽에 쓰는 것 전체. 리소스, 정책, 규칙, 선언 Intent, 확장 등록. 무엇으로 쓰는지(`.aip`, TS, Python)는 T02 | 지난 구현은 `.aip` 파일 |
| **리소스 (Resource)** | 정의에 선언된 데이터 단위. 필드, 관계, 제약, 생명주기를 가진다 | 지난 구현의 `entity` |
| **확장 (Extension)** | 표준 기능 밖의 동작을 JS/Python으로 쓴 것. 타입과 효과 서명을 가진다 | 지난 구현은 런타임 하드코딩 |
| **의미 모델** | 작성 방식과 무관하게 정의와 Intent의 뜻을 하나로 담는 표현. IR은 그 구현 후보 | 지난 구현의 Core Semantic IR |
| **효과 (Effect)** | DB 밖으로 나가는 부작용(메일, 결제, 외부 API, 이벤트) | 같음 |

## 2. SPR 용어

| 용어 | 정의 (초안) |
|---|---|
| Specification | 리소스, 계약, 정책, 동작, 제약, 의도를 표현하는 영역 |
| Presentation | 호출자가 필요한 데이터와 동작을 표현하고 결과를 쓰는 영역 |
| Runtime | 요청을 검증하고 정책을 적용하고 실제로 실행하는 영역 |

경계와 책임은 T05에서 다룬다.

## 3. 자연어 메타데이터와 검증

자연어 메타데이터는 특정 선언에 구조적으로 귀속되는 선택적 설명이다. 자연어 의미 검사는 기본 요구사항이 아니며 실행 권한·보안 판단의 근거로 사용하지 않는다. 구체 키·타입·공개 범위는 T04/DD-05/C에서 설계한다.

필수 실행 안전성 검증은 서버 타입·입력·인증·인가·무결성·트랜잭션·비용 제한이다. 선택적 개발 검증은 정적·구조 검사와 개발 권고다. 같은 알고리즘을 사용해도 실행 의무와 사용 선택은 구분한다.

## 4. 쓰지 않을 표현

| 표현 | 이유 |
|---|---|
| "AIP 언어" | 새 프로그래밍 언어인지가 미정(T02). "정의" 또는 "AIP 문법"으로 쓴다 |
| "API를 호출한다" | AIP가 바꾸려는 모델의 말. "Intent를 보낸다"로 쓴다 |
| "임의 쿼리" | 무제한 요청과 경계 안 조합 요청을 구분하지 못한다. "조합 Intent"와 "무제한 요청"으로 나눠 쓴다 |
