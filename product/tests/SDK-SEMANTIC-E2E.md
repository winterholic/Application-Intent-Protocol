# SDK semantic end-to-end coverage

`sdk-semantic-e2e.test.mjs` runs the declared AIP contract through the real `aip service`, the generated TypeScript binding and installed `@aip/sdk`, and the binding emitted by `aip service gen --lang python` together with the official Python transport runtime. The Python journey imports the generated `read_record` and `apply_record_edit` helpers and passes the generated module's `CONTRACT_FINGERPRINT` to the client. Both clients use JWT authentication and a disposable PostgreSQL 17 service. The test checks each client result and then queries fixture rows directly.

## Migration journey and limits

The migration extension in `sdk-semantic-e2e.test.mjs` uses a new uniquely named schema for each generated SDK language. It calls `service init` on V1, writes through the generated V1 binding and official SDK, stops the service, adds one nullable `Record.migrated` field, and exposes that field only through the V2 fixture's read projection and edit patch. It obtains the product's migration plan, rejects an incorrect digest, applies the plan's exact digest, and restarts the service with V2. Generated V2 bindings then read the preserved row and write the new field. Direct SQL checks confirm the existing Decimal text, `NULL`, relation row, effect counter, and idempotency rows.

This establishes compatibility for the tested additive nullable-field migration on PostgreSQL 17. After migration, both stale V1 generated SDKs attempt a read and an apply with a valid unique idempotency key; the tests assert `WIRE.CONTRACT_MISMATCH`, unchanged record values/effect count, and an unchanged `aip_idem` count before the V2 writes. It does not establish downgrade/rollback behavior, destructive or non-null schema changes, concurrent/zero-downtime rollout, or general schema compatibility across arbitrary definitions. No production migration activation is part of this test.

Migration-contract evidence is reused from the Linux App packages workflow at [`app-deploy-live.test.mjs`](./app-deploy-live.test.mjs), which verifies the digest gate, row and idempotency preservation, and old-definition schema fence. Its optional worker path verifies durable-job state/result preservation for the generated TypeScript and Python SDKs. The SDK-specific migration test adds generated binding calls and checks actor binding through the post-migration SDK session result.

Run locally only with a disposable PostgreSQL 17 target using the guarded `AIP_TEST_DATABASE_URL`; do not initialize a local cluster. CI runs this suite on Linux PostgreSQL 17 in `.github/workflows/sdk-semantic-e2e.yml`.
