# 03. Typed IR 초안

> 상태: Proposed · 표기는 Rust 타입 문법(구현 언어 후보와 일치). 직렬화는 버전 붙은 JSON(`aip-ir/0.1`)과 바이너리(postcard 등, 확인 필요) 두 가지.

## 1. IR의 층

```
Surface AST  ──lower──▶  Core IR (L1)  ──analyze──▶  Verified IR + Obligations  ──plan──▶  Execution Plan
 (문법, 위치)             (의미만)                     (증명 결과, 남은 런타임 의무)         (어댑터가 실행할 단계)
```

| 층 | 누가 만든다 | 누가 소비한다 | 안정성 약속 |
|---|---|---|---|
| Surface AST | parser | formatter, LSP, lowering | 없음 (문법 바뀌면 바뀜) |
| Core IR | lowering, **또는 LLM/도구가 직접** | analyzer, contract 생성 | 버전 관리, 하위 호환 규칙 있음 |
| Verified IR | analyzer | planner, `aip verify` 보고서 | 내부 |
| Execution Plan | planner | runtime | 내부, `aip explain`으로 사람이 읽는 형태 제공 |

Core IR이 공개 계약이다. DSL 문법이 여러 개가 되거나(예: YAML 프런트엔드, 비주얼 편집기) LLM이 IR을 직접 생성해도 analyzer는 같다.

## 2. 식별자와 출처

```rust
struct Id(u32);                        // 모듈 내 고유
struct QualName { module: Symbol, name: Symbol }   // "shop::Order"
struct Span { file: FileId, start: u32, end: u32 } // 진단과 LSP용. 도구 생성 IR은 None 허용
struct Origin { span: Option<Span>, lowered_from: Option<FormRef> }  // 어떤 L3 형식에서 왔는지
```

`lowered_from`은 진단 품질에 결정적이다. `lifecycle`이 만든 require가 실패하면 오류는 require가 아니라 lifecycle 선언 위치를 가리켜야 한다.

## 3. 타입

```rust
enum Type {
    Scalar(Scalar),                    // Bool, Int(i64), Decimal(p,s), Text{max}, Uuid, Time, Date, Duration, Json
    Money(Currency),
    Enum(EnumId),                      // ordered 여부는 EnumDef에
    Record(RecordId),                  // 입력/출력용 구조체
    Ref(EntityId),                     // 엔티티 참조 (값은 id)
    Set { of: Box<Type>, max: u32 },   // 입력 집합, 상한 필수
    List { of: Box<Type>, max: u32 },
    Optional(Box<Type>),
    Range(Box<Type>),                  // Range<Time> 등
    Upload(UploadSpec),                // 크기/타입 제약 포함
    Ext(ExtTypeId),                    // extension 제공 타입 (redis Counter, s3 Object ...)
}
```

- 모든 컬렉션 입력에 상한이 있다. 상한 없는 입력은 IR에서 표현 불가능하다(적대적 클라이언트 가정).
- `Ext` 타입은 extension manifest가 정의하며 Core는 불투명하게 다룬다. 단 저장 표현(storage repr)과 비교 가능 여부를 manifest가 선언해야 한다.

## 4. 스키마

```rust
struct Entity {
    id: EntityId, name: QualName, origin: Origin,
    personal: bool,
    fields: Vec<Field>,
    constraints: Vec<Constraint>,
    visibility: Option<Predicate>,          // `visible to actor when ...`
    lifecycles: Vec<Lifecycle>,
}

struct Field {
    name: Symbol, ty: Type, default: Option<Expr>,
    personal: bool,
    kind: FieldKind,
}

enum FieldKind {
    Stored,
    Reference { target: EntityId, on_delete: RefPolicy, on_erase: Option<RefPolicy> },
    Inverse { target: EntityId, via: Symbol },           // one-to-many 역방향
    Derived(Derivation),                                  // count(...), running_sum, 순수 fn
    External { ext: ExtId, spec: ExtFieldSpec },          // redis counter 등
}

enum RefPolicy { Cascade, Restrict, SetNull, Anonymize, Reassign(RuleId) }

enum Constraint {
    Unique { cols: Vec<Symbol>, filter: Option<Predicate>, code: ErrorCode },
    AtLeastOne { filter: Predicate, per: Vec<Symbol>, code: ErrorCode, repair: Option<RepairRule> },
    NoOverlap { range: Symbol, per: Vec<Symbol>, code: ErrorCode },
    Check { name: Symbol, pred: Predicate },
    Capacity { count: SetExpr, limit: Expr, code: ErrorCode },      // 데이터에서 온 상한
}

struct Lifecycle { field: Symbol, transitions: Vec<(Vec<EnumVariant>, Vec<EnumVariant>)>, code: ErrorCode }
```

`exactly one`은 L3 형식이므로 IR에는 `Unique{filter}` + `AtLeastOne`으로 들어온다.

## 5. 관계와 식

```rust
struct Relation { id: RelationId, params: Vec<Param>, result: RelResult, body: Query0 }
enum RelResult { Bool, One(EntityId), Many(EntityId) }

enum Expr {
    Lit(Literal),
    Param(ParamId), Actor, Now,
    Path { root: Box<Expr>, steps: Vec<Step> },     // 깊이 제한 없음. 모든 경로는 읽기 집합에 등록된다
    Rel { rel: RelationId, args: Vec<Expr> },
    Exists(Box<SetExpr>), Count(Box<SetExpr>), Sum(Box<SetExpr>, Box<Expr>),
    All(Box<SetExpr>, Lambda), Any(Box<SetExpr>, Lambda),
    Unary(UnOp, Box<Expr>), Binary(BinOp, Box<Expr>, Box<Expr>),
    In(Box<Expr>, Vec<Expr>),
    Call(FnId, Vec<Expr>),                           // 순수 함수만
    If(Box<Expr>, Box<Expr>, Box<Expr>),             // 식 수준 조건. 제어 흐름 아님
}

enum SetExpr {
    Scan { entity: EntityId, alias: AliasId },
    Filter(Box<SetExpr>, Predicate),
    Via { from: Box<SetExpr>, path: Vec<Step>, alias: AliasId },   // 조인
    Param(ParamId),                                                 // Set<T> 입력
    Latest(Box<SetExpr>, Expr),                                     // 정렬 기준 최신 1건
}

type Predicate = Expr;   // 타입이 Bool인 Expr
```

모든 `Expr`은 analyzer 이후 `ty: Type`과 **null 의미**(3값 논리가 아닌 명시적 규칙: `actor`가 없으면 actor 경로의 비교는 false)를 가진다.

## 6. Intent

```rust
struct Query {
    id: IntentId, name: QualName, params: Vec<Param>,
    allow: Policy,
    source: SetExpr, sort: Vec<SortKey>, page: Option<PageSpec>,
    selection: Selection,
    cache: Option<CacheSpec>,
    observations: Vec<EffectCall>,          // observational 효과만 허용
}

struct Command {
    id: IntentId, name: QualName, params: Vec<Param>,
    idempotency: Option<IdempotencySpec>,   // key 식, 보존 기간
    lets: Vec<Let>,                          // 불변 이름 값. 실패 코드 가능 (same(...) 등)
    allow: Policy,
    requires: Vec<Require>,
    body: Vec<Stmt>,
    emits: Vec<Emit>,
    returns: Option<(Expr, Selection)>,
}

struct Let { name: Symbol, value: Expr, fail: Option<ErrorCode> }
struct Policy { expr: Predicate, deny_code: Option<ErrorCode>, disclose_existence: bool }
struct Require { pred: Predicate, code: ErrorCode, origin: Origin }

enum Stmt {
    Insert { entity: EntityId, from: Option<SetExpr>, values: Vec<(Symbol, Expr)>, bind: Option<BindId> },
    Update { target: SetExpr, assigns: Vec<Assign> },   // Assign = Set(expr) | Add(expr) | Sub(expr), 집계 필수 여부 포함
    Upsert { entity: EntityId, keys: Vec<Symbol>, values: Vec<(Symbol, Expr)>, bind: Option<BindId> },
    Delete { target: SetExpr },                          // soft delete 엔티티면 하강 시 Update로 바뀜
    Purge { target: SetExpr },
    EachPartial { source: SetExpr, alias: AliasId, body: Vec<Stmt> },   // 항목별 savepoint, 상한 있는 입력만
    ScheduleAt { at: Expr, intent: IntentId, args: Vec<Expr> },         // 내구성 타이머 등록
    Erase { target: SetExpr },                           // personal 엔티티 전용. 참조 정책으로 확장됨
    Effect(EffectCall),
    When { cond: Predicate, body: Vec<Stmt> },           // 입력 존재/불리언만. 중첩 1단계
}

struct EffectCall { effect: EffectId, args: Vec<Expr>, bind: Option<BindId>, origin: Origin }
```

`Stmt`에 루프가 없다. 집합 크기에 비례하는 작업은 전부 `SetExpr`을 대상으로 한다.

## 7. 효과 서명 (extension이 제공)

```rust
struct EffectSig {
    id: EffectId, ext: ExtId, name: Symbol,
    params: Vec<Type>, result: Type,
    class: ConsistencyClass,             // Local | Staged | Reservable | Deferred | Observational
    idempotency: Idempotency,            // Natural | Keyed { key_param } | None
    resolvability: Resolvability,        // 결과를 모를 때: Lookup(EffectId) | None
    compensation: Option<EffectId>,      // Reservable의 cancel, Irreversible+Refundable의 refund
    confirm: Option<EffectId>,           // Reservable의 capture/confirm
    reversibility: Reversibility,        // Reversible | Compensable | Irreversible
    capabilities: Vec<Capability>,       // 네트워크 대상, 비밀 이름 등. 런타임이 강제
    latency_class: LatencyClass,         // 계획 비용 추정용
}
```

analyzer의 효과 규칙은 이 서명만 본다. extension 구현이 서명과 다르게 동작하는 것은 런타임 샌드박스와 conformance 테스트로 막는다(`06-extensions.md`).

## 8. 분석 결과: 의무 (Obligations)

analyzer는 각 Command에 대해 다음을 계산해 Verified IR에 붙인다.

```rust
struct CommandFacts {
    read_set: Vec<FieldRef>,             // 문맥 조회에 필요한 모든 경로
    write_set: Vec<FieldRef>,
    lock_set: Vec<LockTarget>,           // 쓰기 대상 + 불변식 검사 대상, 전역 정렬 순서
    invariants_touched: Vec<ConstraintRef>,
    invariant_proofs: Vec<(ConstraintRef, ProofStatus)>,   // Preserved | Enforced(Db) | Deferred | Unknown
    effect_plan: EffectPhases,           // pre-commit / in-tx / post-commit 배치
    retry_safety: RetrySafety,           // AutoRetryable | ClientRetryWithKey | NotRetryable
    authority_writes: Vec<RelationRef>,  // 이 명령이 바꿀 수 있는 권한 관계 (권한 상승 분석)
    error_codes: Vec<ErrorCode>,         // 계약에 실리는 완전한 목록
}

struct QueryFacts {
    read_set: Vec<FieldRef>,
    invalidated_by: Vec<(IntentId, KeyDerivation)>,   // 캐시 무효화 자동 도출
    plan_cost: CostEstimate,
}
```

`authority_writes`는 새로운 분석이다. 권한 관계(`membership.role`)를 쓰는 명령을 모아 "이 명령으로 누가 누구의 권한을 올리거나 없앨 수 있는가" 그래프를 만든다. 자기 권한 상승(예: MANAGER가 자기 role을 ADMIN으로), 관리자 소멸(예: 아리아리 자기 위임)이 이 그래프에서 드러난다.

## 9. 실행 계획

```rust
struct CommandPlan {
    admission: Admission,                // 입력 디코드, 인증, rate limit, 멱등 키 선점
    pre_commit: Vec<PlannedEffect>,      // staged 업로드, reservable 예약
    tx: TxPlan,
    post_commit: Vec<PlannedEffect>,     // outbox로 넘어갈 것
    response: ResponsePlan,
}

struct TxPlan {
    isolation: Isolation,                // ReadCommitted(기본) | Serializable(불변식이 요구할 때)
    lock_stmt: Vec<SqlTemplate>,         // 정렬된 FOR UPDATE
    context_fetch: SqlTemplate,          // 읽기 집합 + 권한 + 사전조건 재료를 한 번에
    checks: Vec<Check>,                  // 메모리 평가 또는 SQL 평가
    mutations: Vec<SqlTemplate>,         // 집합 연산
    outbox: Vec<OutboxTemplate>,
}
```

planner 출력은 결정적이어야 한다. 같은 IR과 같은 capability 집합이면 같은 계획이 나온다. `aip explain`은 이 구조를 사람이 읽는 단계 목록으로 출력하고, `aip explain --sql`은 실제 SQL을 보여준다.

## 10. 버전 규칙

- IR 문서는 `{"aip-ir": "0.1", ...}`로 시작한다.
- 0.x 동안은 깨질 수 있다. 1.0 이후 minor는 필드 추가만.
- 배포된 계약(contract)과 새 IR을 비교해 클라이언트 호환성을 판정한다(`aip diff --against deployed`): 입력 필드 추가(필수) = 깨짐, 출력 필드 삭제 = 깨짐, 오류 코드 추가 = 경고, 정책 강화 = 경고(행동 변화).
- 구현: 규칙 목록은 `aip-contract/src/compat.rs`(`aip diff`), 스키마 쪽 차이(엔티티, 필드, 이름 변경 `was`, 삭제 `removed`, enum, 제약)는 `aip-ir/src/diff.rs`다. 둘 다 SQL을 모른다. 선언 `was`/`removed`가 IR에 들어가므로 IR 버전은 0.11이다(선언이 없는 프로그램의 직렬화는 이전과 같다). 배포 기록과 스키마 진화는 `spec/grammar.md`의 "스키마 진화" 절.

## 10.1 L3 형식의 IR 표현

`verification`, `grant link`, `approval`, `job`, `expose`, `retain`, `rule`, `projection`, `outbound webhooks`, `consent`, `impersonate`는 IR에 고유 노드가 없다. 전부 엔티티 + intent + 제약 + 타이머 + 효과로 하강한다. IR에 남는 것은 `Origin.lowered_from`뿐이다. 이것이 "L1은 작게 유지된다"(`02` 1절)의 구체적 의미다.
